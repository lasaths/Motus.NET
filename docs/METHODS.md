# Methods catalog

Motus.NET keeps method provenance close to API contracts. Units are explicit at the call surface: joint coordinates use each `JointLimit.Unit` (`Radians` or `Meters`), TCP positions are meters, orientations are quaternions with tolerances in radians, and times are seconds.

| Area | API | Method / status | Units and failure surface | References |
|------|-----|-----------------|---------------------------|------------|
| URDF / xacro import | `UrdfRobotLoader.LoadXacro`, `LoadTreeXacro` | Minimal in-process xacro subset: include, property, simple macro/call, `${arg}` substitution. `$(find)` is rejected. | URDF meters/radians; `NotSupportedException` for `$(find)`, `InvalidOperationException` for malformed trees. | `docs/urdf-import.md` |
| Joint LIN | `JointLinearPlanner` | Joint-linear interpolation with optional collision validation. | Joint coordinates follow `JointLimit.Unit`; collision returns `planning.path_collision`/endpoint codes. | Deterministic managed implementation. |
| Cartesian LIN | `CartesianLinearPathPlanner` | TCP-linear interpolation with IK at samples and optional collision/constraint validation. | TCP meters, orientation radians; IK failures are explicit LIN status strings. | Deterministic managed implementation. |
| PoE FK/IK | `ProductOfExponentials`, `PoEJacobian`, `NumericalInverseKinematics` | Modern Robotics Product of Exponentials and body-Jacobian numerical IK for URDF serial chains. | Revolute radians, prismatic meters; `NumericalIkFailureReasons` names non-convergence/singularity/invalid input. | Lynch & Park, *Modern Robotics*. |
| TOTG | `RetimerAlgorithm.Totg`, `TrajectoryRetimer` | Managed TOPP-RA-style retiming using path parameter `s`, backward controllable squared-velocity intervals, and forward greedy acceleration under separable joint limits. | Velocity/acceleration read from `JointLimit` in that axis unit; invalid NaN/Inf or non-positive limits throw named exceptions. | `TotgMethodRefs`, Pham & Pham 2018, DOI `10.1109/TRO.2018.2819195`. |

| Holonomic SE(2) mobility | `PlanningOptions.Mobility`, `MobilityBounds`, `MobilityModel.HolonomicSE2` | Managed sampling appends x/y/yaw to the plan space and validates collision/constraints with a per-sample base-frame override. Native bridge is bypassed for mobility. | Base x/y in meters, yaw radians; z is fixed during sampling; bound violations return `planning.invalid_options`. | `MobilityMethodRefs`: LaValle, *Planning Algorithms* (2006), `http://planning.cs.uiuc.edu/`. |
| Legged N-leg Walk | `LeggedMechanism`, `GaitSchedule`, `LeggedGait.TryBuild`, `ILegIkSolver`, `IBodyPoseSolver` | General N-leg mechanism + Song–Waldron duty factor β schedule; Walk solver packs `DriverOffsets`, IK-fail out of support, TerrainSupport/PathFollow body pose. `LeggedLayout` remains a test/legacy factory (`ToMechanism`). | `Family=legged`; joints radians; body/terrain/SSM meters; N≤3 static rejected unless `AllowDynamicGait`. | `LeggedMethodRefs`: Lynch & Park; Song & Waldron DOI (β); McGhee & Frank DOI; Bretl & Lall DOI. |

| Legged full-driver Plan adapter | `LeggedGait.ValidateForPlan` | Adapter over `LeggedGait.TryBuild` output only: checks minimum McGhee–Frank SSM and optional collision, then returns `PlanningResult`. ## ADR wave notes

- Serial tip-path and full group planning are distinct contracts: tip FK/IK is for TCP goals; `GroupMap` is for full-driver subsets (including branched grippers/tools) and must be keyed by `RobotModel.JointNames`.
- Parallel Stewart planning is a sibling stack, not a serial tip chain. Its `JointState` values are leg lengths in meters; sampling `StepRadians` / `MaxJointStepRadians` names are historical generic step knobs.
- Legged Walk owns rich gait UI (Path/Terrain/Speed/Step/Lift). Motus Plan synthesizes via `LeggedGait.PlanBodyPath` when a body-path polyline is supplied; `ValidateForPlan` remains the adapter-only SSM/collision gate (Plan hard-fails SSM; Walk may soft-warn).
